## Steps and contracts

| Stage | Input | Action and Android view | Carried output / guard |
|---|---|---|---|
| 01. Import | `ACTION_OPEN_DOCUMENT` URI and display name | Read at most 25 MiB on background executor; call `GpxEngine.analyze` before enabling Continue; display track counts, segments, distance, elevation range | `Source(uri, name, original bytes, stats, SHA-256)`; only valid GPX 1.1 advances |
| 02. Configure | Validated `Source` and persisted user inputs | Prefix (exactly 3 letters), interval (1–100 integer km), expandable algorithm, online geocoding, HTTPS provider, metadata mode | Validated `Options` and options revision; no HTTP lookup at this step |
| 03. Generate | Source byte snapshot and frozen options | Begin once; fresh `GpxEngine.analyze` then `generateWaypoints` and `enrich`; indeterminate indicator; Cancel & back invalidates outstanding result | `Output(result, filename, source SHA, options revision, run ID, warnings)`; only matching successful generation advances |
| 04. Review | Current `Output` | Computed track statistics, exact generated marker IDs, unresolved-geocoding warning, adjust-parameters action | Explicit `reviewed=true` before Export |
| 05. Export | Reviewed current output | `ACTION_CREATE_DOCUMENT` with `application/gpx+xml`; write, flush and close stream on worker thread; cancellation retains result | Saved URI only after successful close; errors allow retry |

### Navigation and stale-result prevention

- Forward moves cannot skip a stage; guard conditions are enforced in `GuidedSession`, independent of Android widgets.
- Back preserves source and options. A successful generation can be revisited without repeating the operation if unchanged.
- Any settings modification increments the options revision and discards output, review and export eligibility.
- A new or replaced input discards all derived output, even when its content has the same SHA-256 as a prior source.
- Each generation reparses original bytes to avoid duplicate waypoint insertion in the mutable GPX DOM.
- Discarding an in-flight request invalidates the run ID. Already-running background code may finish, but its result cannot replace newer state.
- Online geocoding is opt-in; missing descriptions are reported without implying that the GPX transformation failed.
- A canceled save leaves the generated result available. Android's document provider determines the destination and may leave a partial file on I/O error.

### Android lifecycle limitation

On Android Activity recreation (rotation/process recreation), the selected source URI and configuration are saved in `onSaveInstanceState`. The source is **revalidated** from its URI; the derived output is intentionally not placed in the Binder state Bundle. The user must regenerate before Review/Export. Persistable URI permission is requested, but some providers may deny persistent access. No guaranteed continuation of long-running network operations after process termination is claimed.

## Build on the Linux Docker host

```bash
bash tools/test-core.sh
bash tools/test-guided.sh
bash tools/build-apk-docker.sh
```

The Docker build additionally runs `:app:testDebugUnitTest` (including `GuidedSessionTest`) and then `:app:assembleDebug`. When successful, the file is:

```
dist/TrailOneGPX-debug.apk
```

On build failure, complete logs are captured on the Linux host in `android-build.log`. The project pins Gradle 8.13 / AGP 8.11.1 / Kotlin 2.2.21 / Java 17 / Android platform 36 (unaltered from the earlier Android 16 source).

Install on a development device with USB debugging:

```bash
adb devices
adb install -r dist/TrailOneGPX-debug.apk
```

**Debug signing:** Android debug keystores generated by fresh Docker images may differ between builds. If `INSTALL_FAILED_UPDATE_INCOMPATIBLE` occurs, either keep a stable debug signing identity or uninstall the previous debug app first (`adb uninstall com.trailone.gpx`, which deletes its app data) before installing. This is **not a signed production release**.
