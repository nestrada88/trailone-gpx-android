# Approved five-stage guided workflow — implementation contract

**Approval boundary:** The owner approved the **five-stage sequential guided UX proposal as an implementation baseline**. This document preserves that workflow and its data contracts. Component styling, launcher icon, typography, extra features and final production UX are not independently approved by this decision.

## Stage contracts

| Stage | Input | Operation | Carried output | Exit guard | Failure/cancel |
|---|---|---|---|---|---|
| 1 Import | User-selected `.gpx` URI/read grant | Bounded read; parse/validate GPX 1.1; compute source statistics | URI, name, source bytes, SHA-256, statistics | Valid analyzed source | Specific error; remain at Import; retry/replace |
| 2 Configure | Current valid source | Enter prefix `[A-Z]{3}` (default HIK), interval `1..100` km (default 1); optionally select algorithm, geocode HTTPS provider, metadata mode | Validated options and options revision | Validation passes; source unchanged | Block Next with actionable error; retain fields |
| 3 Generate | Original source bytes + frozen options | Reparse; generate markers; optionally reverse-geocode; serialize output | GPX bytes, result statistics, exact marker list, warnings, source hash, options revision, run ID | Matching current successful output | Retry failure; cancel/back invalidates in-flight run and result |
| 4 Review | Current generated result | Display metrics, exact marker IDs and warnings | Reviewed flag for current run | Explicit user continuation and current output | Adjust parameters invalidates output; regenerate |
| 5 Export | Reviewed current output | Android system `ACTION_CREATE_DOCUMENT`; write/flush/close | Selected destination URI, success/failure | Completed write without error | Cancel keeps output; failed write allows retry |

## Mandatory state rules

1. Stage transitions are sequential: no skipping forward; backward navigation is permitted and retains source/options.
2. The original document must never be overwritten intentionally.
3. Replacing source discards prior results even when a filename or bytes happen to match a prior import; new session provenance remains distinct.
4. Modifying any option invalidates derived results, review status and export eligibility.
5. Results may be accepted only for matching run ID, source digest, and options revision.
6. Review data must originate from the actual engine output; mock/demo data must be prominently labelled.
7. Progress reporting must not invent percentage or network counts.
8. Geocoding remains disabled unless explicitly enabled; network coordinate sharing must be clear.
9. Failed optional geocoding must surface incomplete enrichment without falsely reporting GPX processing as failed.
10. Export cancellation/failure never silently discards a valid current result.

## Marker and output semantics

- Core marker names: `<PREFIX>_TH`, `<PREFIX>_TE`, `<PREFIX>_LE`, `<PREFIX>_HE`, `<PREFIX>_MP` and interval markers `<PREFIX>_KM001` (etc.) as generated by the current engine.
- Preserve segment boundaries for distance accumulation. Provide ascent/descent, elevation extrema and total distance in consistent technical units.
- Output GPX 1.1 is a **new serialized file**; preservation refers to structural GPX content where supported, not byte-identical original XML.

## UI structure and accessible interaction

One step visible at a time; progress indicator with labels; fixed primary action per stage; contextual Back; inline validation; expandable advanced controls. Native UI targets should be at least 48 dp, expose semantic labels to accessibility services, support increased font scale, and avoid silent failures. All applied color values must match the eight approved palette tokens.

The approved TrailOne trail-cover geometry, exact cover typography, and mocked home-screen icon are not general Android screen templates. Do not import their crop or coordinate rules into the app.
